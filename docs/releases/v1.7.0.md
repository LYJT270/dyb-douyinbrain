# 承意 · CY-CharmYee 1.7.0

2026-11-13 · Windows

## 中文

本版将个人知识库扩展为生活、工作、学习三个方向，并让已启用的知识库能更自然地参与日常任务。访谈、资料使用、历史库迁移和新版提醒都保留用户现有范围与明确授权边界。

### 功能与变化

- **生活、工作、学习三方向。** 新启用个人知识库后，三个方向默认都参与。起步时依次可选 1 学习、2 工作、3 生活；选择决定先从哪里开始，不会把其他方向排除。新库按 `生活/`、`工作/`、`学习/` 分类；创作内容归入工作，旧 `creative` 字段和模块入口继续兼容。
- **持续但不打断任务的访谈。** 每轮只问一个有用问题。基础资料已经齐全也不会自动结束；用户暂停、停止或换话题时才停下。用户提出明确任务时先完成任务，不强制转成访谈。
- **日常任务读取并积累相关信息。** 在用户已开启的范围内，生活、工作、学习相关任务会主动读取有用背景并据此处理；可积累用户明确提供的新情况、目标变化和实际成果。普通聊天不会被全量归档；暂停、不保存和拒绝的主题仍受尊重。
- **完整、可恢复的旧库迁移。** 迁移前先读取现有导航并生成完整文件映射预览，向用户展示后只确认一次。预览会拒绝重复的规则或导航替换目标，Windows 下大小写等价的路径也视为重复。用户确认后先备份，再重分类并修复支持的链接、索引和运行入口状态。历史回执原样保留，通过独立映射定位迁移后的文件；冲突和后续人工修改受保护，迁移可恢复。使用 `target_rules` 的库仍由其现行写入规则和入口控制，迁移不能绕过目标库发布器或规则。
- **各聊天独立的新版本提醒。** 套件参与的聊天可各自收到一次同一新版提醒；同一聊天不重复，另一个聊天不受影响。24 小时 Release 元数据缓存与聊天去重独立。通知状态目录不可写时，当前对话仍可获得提醒信息供 Agent 去重；工具返回提醒不等于用户一定看到了，实际可见行为取决于宿主。只提示，不自动安装；仅按用户明确要求更新。

### 升级与兼容

已经安装承意 1.6.0 的用户可通过现有更新入口正常更新，使用 `update --apply` 安装。安装程序不会自动迁移真实个人知识库，也不会扩大已有收录范围。要迁移既有知识库，须另行查看完整映射预览并确认一次。

旧 `dyb-*` 或 `douyin-brain` 品牌版本首次迁移到承意仍须运行新安装器，不能用旧品牌更新器直接跨产品升级；完成迁移后再按承意的正常更新流程更新。详见[维护与发布指南中的已有用户升级说明](../RELEASING.md#已有用户如何升级)、[个人知识库说明](../../references/personal-vault.md)和[三方向工作方式](../../references/personal-domains.md)。

### 验证范围

发布前最终全量行为测试 **246 项通过，耗时 200.980 秒**，包含新增的重复迁移目标回归。迁移专项 **11 项通过**，提交前审查发现的问题已修正并由独立 Reviewer 复审通过。GitHub CI、标签、源码提交和公开安装包校验以本 Release 的公开验证附录为准。

真实 Codex CLI 新会话中，未点名 Skill 时主动读取虚构资料、按用户给出的学习背景和时间安排处理任务，并保存原始要求与实际成果；读回内容与回执一致。隔离刷新安装保留既有配置、任务和成果文件，登记 7 个套件入口；实际安装布局下的迁移、历史回执保持不变及回滚通过。更多候选阶段证据见[三方向候选验证记录](../verification/three-domains-candidate.md)。

新版提醒的命令层同聊天去重、跨聊天独立提醒及只读通知状态回退有验证。终版“用户可见提醒”复验被宿主执行策略拦截；Codex 桌面、Claude 等其他宿主的实际新会话行为也未验收，因此不能据此承诺每种宿主都已显示提醒。本轮未进行真实语音请求、抖音全量处理或真实用户知识库迁移。

## English

Version 1.7.0 expands the personal vault to life, work, and learning, and lets an enabled vault contribute more naturally to everyday tasks. Interviewing, context use, legacy-library migration, and update notices remain within the user's existing scope and authorization.

### Features and changes

- **Three personal domains.** All three domains participate by default when a personal vault is newly enabled. The starting choices are 1 Learning, 2 Work, and 3 Life. This selects the first interview focus; it does not exclude the other domains. New libraries use `生活/`, `工作/`, and `学习/`. Creative work belongs under Work, while the legacy `creative` field and module remain compatible.
- **An interview that continues at the user's pace.** Ask one useful question per turn. Filling the basic profile does not end the interview; pause when the user pauses, stops, or changes topic. Complete a concrete task first instead of forcing it into an interview.
- **Relevant context in everyday tasks.** Within the user's enabled scope, related life, work, and learning tasks can retrieve useful context and use it in the work. The vault can collect explicit new information, changed goals, and actual outcomes. It does not indiscriminately archive ordinary conversation, and it respects paused, declined, and unsaved topics.
- **Reviewed and recoverable migration.** Read the existing navigation and prepare a complete file-mapping preview before asking the user for one confirmation. The preview rejects duplicate rule or navigation replacement targets, including Windows case-equivalent paths. After confirmation, back up the original library, reclassify files, and repair supported links, indexes, and runtime entrypoints. Keep historical receipts unchanged and resolve their old paths through a separate mapping. Protect conflicts and later human edits, and allow recovery. Libraries using `target_rules` remain controlled by their current write rules and entrypoint; migration cannot bypass the target publisher or its rules.
- **Independent update notices per chat.** Each participating chat can receive one notice for the same newer release. Repeated checks in that chat are deduplicated, and one chat does not suppress another. The 24-hour Release metadata cache is separate from chat-level deduplication. If the notice-state directory is read-only, the current conversation can still receive the notice information for in-conversation deduplication. A tool result alone does not prove the user saw it; visible behavior depends on the host. The updater only installs after an explicit user request.

### Upgrading and compatibility

Users already on CY-CharmYee 1.6.0 can use the existing updater and install with `update --apply`. Installation does not migrate a real personal library or expand its existing collection scope. A separate migration requires reviewing the complete mapping preview and confirming once.

An installation still using the old `dyb-*` or `douyin-brain` brand must run the new installer for its first move to CY-CharmYee; its old updater cannot cross product identities. After that migration, use the normal CY-CharmYee update flow. See [existing-user upgrade guidance](../RELEASING.md#已有用户如何升级), [personal-vault documentation](../../references/personal-vault.en.md), and [the three-domain workflow](../../references/personal-domains.en.md).

### Verification scope

Final pre-release behavioral regression passed **246 tests in 200.980 seconds**, including the duplicate-migration-target regression. All **11 migration tests** passed, and an independent Reviewer passed the corrected pre-commit finding. GitHub CI, tag, source commit and public-package verification are recorded in this Release's public verification appendix.

In a real fresh Codex CLI conversation, the Agent used synthetic profile information without the user naming the Skill, adapted work to the stated learning background and available time, and saved the request and actual outcome. Read-back files matched their receipts. An isolated refresh installation preserved existing configuration, task, and output files and registered all 7 suite entries. Migration, unchanged historical receipts, and rollback passed in the installed layout. See the [three-domain candidate verification](../verification/three-domains-candidate.md) for more evidence.

Command-level same-chat deduplication, independent notices across chats, and read-only notice-state fallback were verified. The final test of a user-visible notice was blocked by host execution policy. Real fresh-chat behavior in Codex desktop, Claude, and other hosts remains unverified, so these results do not establish that every host displays notices. This round did not test live speech, full Douyin processing, or migration of a real user's library.
