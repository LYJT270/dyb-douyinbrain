# 抖音脑 Douyin-brain 1.5.0

2026-11-12 · Windows

## 中文

本版改善旧任务续接和素材复用：处理中断后能找到有效成果及下一步；修改旧稿时保留人工编辑；对已有材料换一个分析问题时，建立独立离线任务。

### 功能与变化

- **统一恢复入口。** `resume` 只读查找普通、博主和组合任务，显示目标、有效成果、缺口及下一步。来源或目标有歧义时返回候选，不自动选择最近的任务。
- **沿原范围继续。** 普通任务 `run --saved-scope` 仅处理已保存的作品；恢复博主任务沿用原清单和观察时间。用户明确要求更新时才刷新主页，未发现完整范围的缺口继续保留。
- **逐条保存和版本保留。** 校对稿、口播稿可逐条登记，已完成条目继续复用。新登记保存不可覆盖的快照和来源依据，区分工作稿编辑、文件缺失及下游依据过期。原稿、人工修改及旧交付保留。
- **独立离线分析。** `reanalyze` 和 `creator reanalyze` 根据旧材料创建新任务，原问题和结论保持独立。博主任务可以复用来源和文件版本均有效的历史核对记录；复用不等于当前 Agent 重新看过画面。新问题仍需自己的分析和报告。
- **保留实际进度。** 再次准备素材时保留有效的待领取和已领取核对包。独立条目继续推进；依赖整批材料的结论保留缺口，部分交付明确覆盖范围。
- **既有授权继续有效。** 恢复摘要不执行步骤或授予权限；离线任务不新增获取、语音识别或付费授权。失败和结果未知的付费请求仍须核对，并按用户明确的重试指令处理。

详细用法见[恢复与复用](../../references/continuation.md)。

### 升级与兼容

使用 1.1.0 及以后版本时，对 Agent 说“使用 dyb-douyinbrain 更新”，即可通过官方 Release 更新整套 Skill。旧版 1.3.x 本地候选也可使用同一更新入口。自定义安装沿用原工作目录和安装位置，已有任务与配置无需批量迁移；本次不改变运行依赖。

旧记录仍可读取。不可覆盖的文稿快照从新版本登记开始产生；旧记录没有快照时，不能凭空恢复被覆盖的正文。更新后重读 Skill 或开启新会话。发布新版本不会自动升级维护者的日常安装。

### 验证范围

发布准备阶段本地通过 **173 项行为测试**，其中新增 14 项恢复场景；独立 Agent 使用两篇示例文字完成真实跨 Python 进程续办及独立分析；12 个旧任务通过只读兼容检查，记录哈希不变。详细证据见[本地验收](../verification/workflow-continuity.md)。GitHub Windows CI 另行验证正式提交、全新安装、已有文本交付及安装包完整性。

本轮没有新增真实语音请求。纯文字跨进程试用不等于完整 Codex 应用重启、其他宿主或真实媒体验收；真实媒体完整耗时的提速幅度尚未测量。

## English

This release improves recovery and reuse: interrupted tasks expose valid results and next actions, revisions preserve user edits, and a new question about saved material creates a separate offline analysis task.

### Features and changes

- **Unified recovery.** Read-only `resume` finds ordinary, creator, and combined tasks and reports goals, usable artifacts, gaps, and next actions. Ambiguous sources or goals return candidates rather than selecting the newest task.
- **Saved scope.** `run --saved-scope` processes only saved ordinary-task jobs. Creator recovery retains its catalog and observation time; refreshing a profile requires an explicit update request. Discovery gaps remain visible.
- **Item-level revisions.** Register reviewed text and spoken scripts item by item, retaining completed work. New registrations preserve immutable snapshots and source dependencies and distinguish edited, missing, and stale files. Originals, user edits, and prior deliveries remain available.
- **Separate offline analysis.** `reanalyze` and `creator reanalyze` create new tasks from saved material. Creator analysis can reuse historical review only when its source and file versions remain valid; it does not claim the current Agent viewed those images again. Each question needs its own grounded analysis and report.
- **Durable progress.** Repeated preparation retains valid pending and claimed packets. Independent items can continue while whole-batch conclusions retain unresolved dependencies and explicit partial coverage.
- **Existing authority boundaries.** Recovery guidance does not execute actions or grant permissions. Offline tasks do not acquire new material, submit speech, or carry paid authority. Failed or unknown paid submissions still require investigation and explicit retry instructions.

See [recovery and reuse](../../references/continuation.en.md).

### Upgrading and compatibility

From 1.1.0 or later, including local 1.3.x candidates, ask the Agent to update dyb-douyinbrain through its official Release updater. Existing workspace, installation paths, configuration, and tasks are preserved without a bulk task migration. Runtime dependencies are unchanged.

Legacy records remain readable. Immutable text snapshots start with new registrations; missing historical snapshots cannot reconstruct overwritten text. Reread the Skill or start a new conversation after updating. Publishing does not automatically update the maintainer's everyday installation.

### Verification scope

Local release preparation passed **173 behavioral tests**, including 14 new recovery scenarios, an independent two-document Agent trial across separate Python processes, and read-only checks of 12 existing tasks with unchanged record hashes. See [local verification](../verification/workflow-continuity.md). GitHub Windows CI separately checks the formal commit, fresh installation, existing-text delivery, and package integrity.

This round added no live speech requests. Text-only process recovery does not establish a complete Codex application restart, other-host compatibility, or live-media behavior. End-to-end live-media speedup has not been measured.
