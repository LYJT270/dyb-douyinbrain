# 个人知识库本地验收

日期：2026-11-13。范围：当前源码新增 cy-vault；未发布、未升级日常安装，真实用户库未参与测试。

## 实现范围

- 第六个业务子 Skill，随共享安装器安装；总入口、子入口路由与中英文首次介绍同步。
- 可选建库/已有库接入，固定的个人档案入口，创作和学习模块，一次一问的可跳过/暂停/续接建档。
- 工作区或当前所选 Agent 的读取入口；原文件保留、备份、可识别区块，项目规则优先。
- 范围内主动积累、任务不保存、暂停、不可变快照、来源记录、文件版本核对、索引读回、失败续办。
- 已有库通过其实际写入入口后读回校验；不会安装开发者私有个人助手依赖。

## 自动化验证

使用项目已有依赖环境运行 `python -B -X utf8 -m unittest discover -s tests`，最终 204 项全部通过（135.920 秒），其中个人知识库专项 26 项。个人知识库行为覆盖见 `tests/test_personal_vault.py`；安装、隔离运行、旧版迁移、回退和子入口一致性见 `tests/test_suite_install.py` 等原有测试。

关键结果包括：原始回答与当前档案分别保存；连续回答在存储故障后按先后补存；人工档案合并后继续回答仍保留手写内容；未知或推测不进入事实；重复材料复用已核实目标；已保存目标变化不会被旧回执冒充成功；任务不保存不产生收录快照；原文不覆盖；索引失败恢复不重复写入；已有库保留规则并验证实际文件与索引；过时口播交付不会与新登记稿混用。

首次全量检查使用了缺少 Playwright 的系统 Python，3 项浏览器测试因此报依赖缺失；另有一项旧安装回退断言仍按 6 个入口计算。补齐新入口的 7 项断言后，改用既有完整依赖环境验证，不删除或跳过原测试。

## 独立前向试用

独立 Agent 只获得已安装 Skill、隔离目录和虚构用户请求，无预期答案。实际完成：建库、保存 7 个明确字段及原话、开启创作、写出两个选题和初稿、保存来源与主题笔记，再处理“这次不保存”的短稿请求。

- 4 份创作文件与源文件、快照、回执 SHA-256 一致；25 条库内链接有效。
- 临时改稿前后 41 个文件无新增、无删除，仅跳过任务的状态文件变化；库内 14 份文件不变，下一普通任务仍可保存。
- 新命令进程可通过 `kb context` 找回档案和初稿；通用知识事务使用 kb 续办，普通媒体 resume 不搜索这类记录。路由说明已澄清。
- 试用发现 role 说明缺少合法值，未知角色报错误指向档案权限。已列清角色并给出准确错误，保留 profile 写入边界。

## 真实宿主会话

另起一次 Codex CLI ephemeral 会话，不提供档案答案、不复制原对话。工作区入口被识别，实际读取隔离库档案、原始回答与 kb context，并按该虚构用户的“地图设计系列”和简短表达偏好输出两个相关选题。该轮无联网业务操作、无用户库改动。

前两次宿主尝试受 Windows 临时目录的私有 ACL 限制，不能算通过；改用正常继承权限的隔离目录后，实际读取与输出通过。过程中发现非默认登记目录可能让入口选择错误的 Python，现已让显式 `--workspace` 优先选择该工作区自己的运行时，并补安装后行为测试。

这是 Codex CLI **工作区范围**的实际新会话证据；不等于 Codex 桌面全局范围、Claude Code 或其他宿主的真实会话验收。全局入口生成及保留行为在隔离文件上测试，目标宿主实际加载仍需在对应环境观察。状态中的 host_session 不根据文件生成结果自动提升为已验收。
