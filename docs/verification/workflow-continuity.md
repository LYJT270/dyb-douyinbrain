# 工作流续接与离线分析：本地源码验收

本记录保存 `codex/workflow-continuity` 发布前的本地验收证据。当时尚未提交、推送或发布，也没有替换日常 Skill 安装。新增能力归入 [1.5.0](../releases/v1.5.0.md)，官方 1.4.0 不包含本次改动。GitHub 发布及 CI 状态以对应 Release 和运行记录为准。

## 改动范围

- `resume` 只读查找已有任务并输出目标、有效产物、缺口及下一步，适用于普通、博主和组合任务。来源及目标不明确时返回候选，不猜测最近的任务。
- 恢复保持保存的素材范围。普通任务 `run --saved-scope` 仅执行已保存的作品，保留未发现完整范围的缺口；更新主页仍需明确的更新目标。
- 文稿按成功素材逐条登记，并保存不可覆盖的版本快照、旧登记和来源依据。恢复区分工作文件被编辑、缺失及下游依据过期；交付仍校验实际正文。
- `reanalyze` 和 `creator reanalyze` 创建独立离线任务。普通任务复制有效校对稿；博主任务冻结清单和观察时间，复用已验证的历史核对依据并保留来源。新问题仍需独立分析和报告。
- 离线任务不获取或识别新素材，不继承付费授权或旧会话工具能力。本地材料不足时保留缺口。再次准备保留有效待领取／已领取包。
- 总入口、分析子入口、中英文说明及共享 `guide` 已接入新流程，按明确最终目标连续执行，保持简短进度和聊天成果交付。

运行方法见 [恢复与复用](../../references/continuation.md)；English: [Recovery and reuse](../../references/continuation.en.md)。

## 已完成验证

1. **全套离线行为测试：173 项通过。**
   命令：`python -B -X utf8 -m unittest discover -s tests`。新增的 14 项场景覆盖精确匹配与歧义、源稿变化、逐条登记、人工修改及旧版本保留、下游过期、完成稿复用、独立步骤、工作区移动、新进程恢复、普通与博主离线派生、固定范围恢复、核对包保留和历史核对来源。
2. **独立 Agent 试用通过。**
   在隔离工作区使用两篇自行编写的示例文字，经源码 CLI 完成校对和口播；第一篇登记后退出进程，再由另一进程仅补第二篇；随后另建开头分析。共 29 条业务／统计命令成功，两项原生任务与组合任务最终均无待办。第一篇正文及登记不变，离线派生没有改写原任务。主 Agent 重新读回完成状态及交付哈希。
3. **旧任务只读兼容检查通过。**
   12 个已有任务均可读取恢复信息，检查前后任务记录哈希完全一致。此检查不执行旧任务、刷新来源或提交语音。
4. **Skill 与分发一致性检查。**
   总入口及受影响的分析子入口通过 `quick_validate.py`；`scripts/check_release.py` 通过，`bundle.json` 按最终文件重新生成。验证器的 PyYAML 仅安装在忽略的本地验证目录，不加入产品依赖。

独立试用曾有一次临时核验脚本断言失败：预期合并稿没有编号，而产品既有格式要求 `1.`／`2.`。核查原实现和既有测试后，按原规格精确比较编号、全文、BOM 及 CRLF，并保留首次失败记录；未修改产品格式或削弱原测试。

## 验证边界

- 全套测试涉及语音路径时使用隔离模拟服务，本轮真实语音请求为 0。
- 独立试用是真实的 CLI 退出／新 Python 进程续办，不等于完整 Codex 应用重启、跨宿主验收或日常安装升级。
- 本轮未新增真实抖音采集、整号视觉分析或同批媒体的完整耗时基准，不能据此宣称具体提速倍数。减少重复处理通过缓存、不可重复提交及成果保留的行为结果验证。
- 上述本地验收阶段没有提交、推送、生产发布、知识库写入或业务数据清理。
