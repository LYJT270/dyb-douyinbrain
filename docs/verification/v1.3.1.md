# 1.3.1 本地候选验收 / Local candidate verification

2026-11-06 的本轮本机验收记录。本候选尚未推送、运行本次 GitHub CI 或公开发布；本机检查不等于用户验收。为保护素材和账户，本记录只保留匿名汇总，不列原始链接、作者身份、个人路径或凭据。

## 中文

### 真实获取路径对照

- 本轮使用固定的 14 条公开视频，对 1.3.0 的原有顺序与浏览器优先试验分别获取；两条一组，新旧先后交替，各自使用全新的匿名媒体缓存。共执行 28 次获取，均未调用 ASR。这是本轮重新获取的对照，不是沿用 1.3.0 上一轮的结果。
- 原有顺序成功 **7／14**，浏览器优先试验成功 **6／14**，其中一条原本成功的素材在试验中失败。双方共同成功的 6 条源媒体 SHA-256 均一致；仅对这 6 条，单条获取耗时均值由 **60.6278 秒**变为 **51.5025 秒**，约缩短 **15.1%**。
- 浏览器优先试验损失了一条原有成功结果，未满足本轮质量门槛，因此已撤销。当前保留 HTTP 分享页、匿名无头浏览器及原有回退路径；上述试验耗时不是最终默认版的提速结果。固定样本不能代表所有作品或平台状态。

### 流水线与本地回归

- 在固定模拟获取时延（1.2、0.3、0.3 秒）和模拟识别时延（每次 0.45 秒）下，旧、新流程各运行 3 次并交替执行。总耗时中位数为 **3.196 → 2.657 秒**，约缩短 **16.9%**；首条模拟识别完成时间中位数为 **1.990 → 1.026 秒**，约缩短 **48.4%**。每次运行有 3 次模拟识别，最终结果顺序一致。
- 以上是模拟数据，没有请求豆包，也不代表真实素材的获取、识别或最终校对交付速度。独立模拟正确性检查覆盖最多 2 个获取任务、1 个串行识别，以及重复素材、失败或结果未知请求、中断续跑场景。
- 最终本地全套回归通过 **97 项**，耗时 **54.482 秒**。

### 实际媒体的抽帧对照

- 使用 2 份既有媒体，对 6 个区间各执行一次新旧准备，涵盖全片抽样、局部抽样、逐帧与重叠复用。共输出 **157 帧**，新旧结果的原始帧号、时间戳与 JPEG SHA-256 逐项一致。这个对照不调用 ASR，也不等于 Agent 已看图、听音或完成文稿校对。
- 6 个区间累计准备耗时由 **18.985 秒**变为 **14.015 秒**，约减少 **26.2%**；这是该组抽帧准备耗时，不能当作完整文稿交付的提速。6 个区间中有 5 个更快，首次全片抽样的一次结果为 **3.969 → 4.484 秒**，并非所有场景都更快。
- 其中，60～61.5 秒的逐帧区间为 **1.985 → 0.672 秒**；重叠的 60.5～61 秒区间为 **2.000 → 0.078 秒**，新版复用了 **16 帧**。这些数值只描述本次样本和测试条件。

### 真实语音任务与实际校对

- 本轮账本记录 **3／3 次新豆包请求成功**，累计提交音频 **139.6723125 秒**；没有第 4 次请求，也没有重试付费请求。这是本轮真实请求，不能用 1.3.0 的历史账本替代。
- 第一条冷获取遇到 HTTP 错误，进行一次非付费获取重试后在 90 秒超时；随后使用本轮获取对照中源文件 SHA-256 一致的缓存恢复。其豆包请求耗时 **41.031 秒**，音频时长 **69.591625 秒**；不能把这条记为冷获取成功。
- 第二条冷获取遇到 HTTP 错误，一次非付费续跑后获取成功；其豆包请求耗时 **17.062 秒**，音频时长 **18.786375 秒**。
- 第三条首次冷匿名获取成功：`run` 的 `ready_at_seconds` 为 **61.110 秒**，豆包请求耗时 **33.812 秒**，音频时长 **51.2943125 秒**；从 `plan` 开始到进入待校对状态为 **98.654 秒**，包括 `plan`、`confirm` 和命令调用。
- 第三条的材料准备为 **2.937 秒**，定点补帧为 **0.720 秒**，Agent 校对与登记墙钟为 **75.652 秒**，端到端为 **178.592 秒**。Agent 墙钟已包含定点补帧和文件操作，不能把重叠部分重复相加；这些是单次记录，不代表稳定速度。
- 第一、二条的端到端时间分别为 **632.526 秒**和 **599.948 秒**，其中 Agent 校对与登记墙钟分别为 **145.474 秒**和 **318.725 秒**。这些过程混入获取失败诊断、脚本整理、记录操作及会话压缩，不能作为纯阅读时间或正常交付速度样本。
- 三条均由 Agent 通读全文、各实际查看 **5 帧**，合计 **15 帧**，另存校对稿并交付；机器原稿哈希保持不变。三条都没有听音，第二条的「全天的」保留为未解疑点。看图不能证明实际说话内容，交付也不等于用户验收。
- 本轮没有完整的新旧端到端对照，不能据此声称整体平均提速。

## English

This is a local verification record for this round from November 6, 2026. The candidate has not been pushed, run through this candidate's GitHub CI, or publicly released; local checks do not constitute user acceptance. To protect material and accounts, this record contains anonymous summaries only, without source links, author identities, personal paths, or credentials.

### Live acquisition-path comparison

- In this round, the existing 1.3.0 order and a browser-first experiment each acquired the same fixed set of 14 public videos. Videos were processed in pairs, with the version order alternating and separate fresh anonymous media caches. The 28 acquisition attempts made no ASR calls. This is a new comparison, not a reuse of the previous 1.3.0 round.
- The existing order succeeded on **7/14**; the browser-first experiment succeeded on **6/14** and lost one previously successful item. The source-media SHA-256 values matched for all 6 items that both versions acquired. For those 6 matched successes only, mean per-item acquisition time changed from **60.6278 seconds** to **51.5025 seconds**, approximately **15.1%** shorter.
- Browser-first lost an existing success and did not meet this round's quality criterion, so it was reverted. The current route retains the HTTP share page, anonymous headless browser, and existing fallbacks. The experimental timing is not the final default version's speedup; this fixed sample does not represent all posts or platform conditions.

### Pipeline and local regression

- With fixed simulated acquisition delays of 1.2, 0.3, and 0.3 seconds and a simulated recognition delay of 0.45 seconds per call, the old and new flows were run 3 times each in alternating order. Median total time changed from **3.196 to 2.657 seconds**, approximately **16.9%** shorter. Median time to the first simulated recognition result changed from **1.990 to 1.026 seconds**, approximately **48.4%** shorter. Each run made 3 simulated recognition calls and retained the same final result order.
- These are simulated results: no Doubao request was made, and the figures do not establish live acquisition, recognition, or final reviewed-delivery speed. An independent simulated correctness check covered at most 2 concurrent acquisitions, 1 serial recognition, duplicate media, failed or unknown requests, and interrupted resumption.
- The final full local regression passed **97 tests** in **54.482 seconds**.

### Frame comparison using actual media

- Two existing media files were used for 6 ranges, with one old and one new preparation for each range: full-video sampling, partial sampling, every-frame extraction, and overlapping reuse. All **157 output frames** matched item by item in original frame index, timestamp, and JPEG SHA-256. This comparison did not call ASR and does not mean the Agent viewed images, listened to audio, or completed transcript review.
- Combined preparation time for the 6 ranges changed from **18.985 to 14.015 seconds**, approximately **26.2%** shorter. This is frame-preparation time for this set, not end-to-end transcript delivery speed. Five of the 6 ranges were faster; one first full-video sampling run changed from **3.969 to 4.484 seconds**, so not every case was faster.
- For the 60–61.5 second every-frame range, preparation changed from **1.985 to 0.672 seconds**. For the overlapping 60.5–61 second range, it changed from **2.000 to 0.078 seconds**, with **16 frames** reused in the new flow. These numbers apply only to this sample and test setup.

### Live speech tasks and actual review

- This round's ledger recorded **3/3 successful new Doubao requests**, covering **139.6723125 seconds** of submitted audio. There was no fourth request and no paid request was retried. These are this round's live requests, not the earlier 1.3.0 ledger.
- The first cold acquisition encountered an HTTP error; one unpaid acquisition retry then timed out at 90 seconds. The task was recovered using cached source media with the same SHA-256 from this round's acquisition comparison. Its Doubao request took **41.031 seconds** for **69.591625 seconds** of audio; it is not a cold-acquisition success.
- The second cold acquisition encountered an HTTP error and succeeded after one unpaid acquisition rerun. Its Doubao request took **17.062 seconds** for **18.786375 seconds** of audio.
- The third item succeeded on its first cold anonymous acquisition. Its `run` recorded `ready_at_seconds` of **61.110 seconds**; the Doubao request took **33.812 seconds** for **51.2943125 seconds** of audio. From `plan` to the awaiting-review state took **98.654 seconds**, including `plan`, `confirm`, and command invocation.
- For the third item, material preparation took **2.937 seconds** and targeted frame preparation **0.720 seconds**. Agent review and registration took **75.652 seconds** of wall time; end-to-end time was **178.592 seconds**. The Agent wall time already includes targeted preparation and file operations, so overlapping durations must not be added twice. These are single-run figures, not stable speed measurements.
- End-to-end times for the first two items were **632.526** and **599.948 seconds**, respectively; Agent review and registration wall times were **145.474** and **318.725 seconds**. These processes included acquisition-failure diagnosis, script preparation, recordkeeping, and conversation compaction, so they are not pure reading or normal delivery-speed samples.
- For each of the three items, the Agent read the whole transcript, actually viewed **5 frames** (**15** total), and saved and delivered a separate reviewed version; the original machine-transcript hashes remained unchanged. None of the audio was listened to, and the phrase “全天的” in the second remains uncertain. Viewing frames does not establish what was said, and delivery is not user acceptance.
- This round has no complete old-versus-new end-to-end comparison and does not establish an overall average speedup.
