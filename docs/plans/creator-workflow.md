# 博主全量分析与独立批量下载方案

状态：**本地实现与样本验证完成，未公开发布**。本轮样本结果不代表真实账号全部作品已分析；测试和样本范围见[本轮验证记录](../verification/creator-workflow.md)。

## 目标与边界

- 面向所有用户提供两个可独立使用的入口：**博主全量分析**和**批量下载**。第一阶段支持 Windows，本机 Skill 负责获取、持久化和准备材料，当前宿主 Agent 在实际具备相应能力时完成视觉核对与分析。不默认创建云服务。
- 全量分析以用户指定的公开主页为范围，对当前可访问的作品建立清单、逐条分析，再按时间形成阶段总结和账号总评。视频与图文都纳入；平台没有提供或当前无法访问的内容如实说明。
- 独立批量下载针对用户指定主页中的视频，交付可单独打开的视频文件及每条作品的发布文案和元数据；图文参与分析，下载模式不导出图文，也不调用语音识别。
- 语音识别只使用豆包。新增付费请求先按下述批次规则展示信息并取得授权；功能实现、本机候选安装及离线测试不等于公开发布。

## 处理流程

### 1. 刷新主页并建立可续跑清单

1. 对公开主页逐页发现作品，逐页持久化发现结果及可用的分页进度；以作品 ID 去重，同时保留作品类型、来源、发布时间、标题、发布描述和本次取得的互动数据。无法标准化的原始记录连同所在页面文件和行内索引保留并记入 `discovery.unresolved_records`，不能凭猜测合并。
2. 保留已发现作品和每阶段进度。分页中断、访问受限或出错时显示实际原因；已经发现的部分可以继续处理和交付，主页枚举状态保持不完整。重跑刷新主页并按 ID 去重，未完成的刷新保留本任务已有作品，并标记本轮未见的项目。
3. **先刷新主页，再判断作品缓存**。新一轮增量任务先发现主页当前作品和互动快照，再逐条复用缓存。读取到旧清单或已有缓存不证明主页完整；未到平台返回的分页末尾时，不能报告全量完成。
4. `pagination_complete` 只表示到达分页末尾；页面结果落盘且没有无法标准化的记录时，才可将本次可访问范围的 `discovery_complete` 标为完成。记录获取时间及范围。完整刷新时，本轮未见的旧项不进入本次有效清单，原始页、旧任务和已有材料保留，不推断其已删除。枚举完成、素材处理完成和分析完成分别判断。

### 2. 逐作品准备素材与授权识别

- 主页发现与作品获取分开：每个作品独立获取、验证和记录结果；一个作品超时或失败不抹掉其他作品的成果。原有普通链接流程对输入项调用 90 秒获取 worker，主页发现和多个作品准备可能共用时限；博主任务按逐作品获取计时，豆包识别不纳入该获取时限。
- 获取任务使用有限并发，默认 2 路、可调整为 1–4 路；语音识别默认 1 路，账户额度允许时可调整为最多 2 路。分页、作品获取、识别和宿主分析分别记录状态，续跑时保留成功结果、请求记录和失败原因。
- 视频取得可用媒体，准备完整音轨及对应转写；图文保存可获取的图片序列和文本，不为无音轨内容发起 ASR。音频不可用、识别不完整、作品受限或内容缺失时记录缺口，不能称为完整口播。
- 新增付费请求前，列出待处理作品／请求数量、已知音频总时长、未知时长数量和预计用量；未知部分不得计作零。只有适用的单价、计费单位及账户计费条件明确时才估算费用，否则说明费用暂无法估算。用户对所列批次一次授权后执行；批次之外新增的付费工作须另行获得授权。
- 成功的识别分片与结果按条件复用。付费请求失败或结果未知时保留请求及可核对的信息，不自动重发；先核对状态，再取得用户明确的重试指令。正常的非付费获取失败与付费请求状态分别记录。

### 3. 一次阅读、分开留底

- 每条作品的分析输入包括标题、发布描述、完整口播或明确的音频缺口，以及封面和与内容类型相匹配的关键画面。图文保留并分批阅读内容图片；视频按内容变化、文本信息和疑点选择有代表性的帧，必要时针对时间点补查。留存图像及其作品 ID、顺序或视频时间戳。
- 在同一次阅读中完成视觉核对和逐条分析，但分别保存核对记录与分析结果：核对记录说明实际看了什么、存在什么疑点；分析结果说明内容、表达手法与有证据的判断。后续定点补查可追加，不把准备出的帧当作已看过，也不把看图当作已听音。
- 宿主支持多图输入时批量阅读；支持并行时先尝试最多 2 路视觉任务，能力或资源不足时缩减并如实记录。无法实际读取的材料保持待处理或不完整，不伪造视觉核对和分析已完成。
- 逐条分析使用统一字段和口径，结论关联作品 ID、原文片段、图片或视频时间戳；区分内容事实、分析判断和不确定项。互动量保留获取时间，并结合发布时间、观察时点、作品形式及可得指标解释，不把不同观察窗口的数字直接当作因果证明。

### 4. 按时间归并并交付

- 以作品发布时间从最早到最新排序，置顶作品放回其时间位置；发布时间缺失的作品单列待核对，不猜时间。长周期账号先按时间顺序形成阶段总结，再基于各阶段和作品证据形成账号总评，阶段划分依据及范围要可追溯。
- 全量分析交付逐条简析、按时间排列的阶段总结、账号总评、统一字段 CSV，以及保存来源业务数据的机器可读文件。保留标题、描述、口播／缺口、封面与已取画面引用、作品类型、发布时间、互动快照、来源和各阶段状态；平台未返回的数据标为未知。原始业务字段保留来源值，凭据和浏览器状态不进入交付物。
- 交付标明主页枚举、各作品获取、识别、视觉核对和分析的分别完成情况，以及失败、缺失和可续跑项。部分结果可以交付，但阶段总结和总评必须标注其覆盖范围与局限，不能冒充完整账号结论。

## 独立下载与省空间选项

- 默认选择当前能够获取的最高画质；分别保存每条视频及发布文案／元数据。记录实际取得的格式、画质或可获取的对应信息；无法确认画质时标明未知。
- 每个交付文件可在离开任务缓存后独立打开，元数据至少关联作品 ID、来源链接、发布时间、发布文案、作品类型和实际获取状态。下载入口可以复用合格媒体缓存，不启动 ASR。
- 允许用户明确选择省空间方案，例如选用更省空间的可用版本或编码，并说明实际质量／格式变化。默认保留最高画质；不因开启该选项擅自清理已有用户文件。

## 增量复用与状态口径

媒体、转写、帧图和分析分别判断是否可复用：

| 层次 | 复用条件与变化处理 |
| --- | --- |
| 媒体 | 作品 ID、内容及本地文件校验匹配时复用；内容或文件发生变化时重新核对受影响素材。 |
| 转写 | 音频内容、识别参数和版本匹配时复用；只改变分析要求不重新识别，重新识别须有明确要求及必要的付费授权。 |
| 帧图 | 来源媒体、采样位置及处理条件匹配时复用；现有画面不能支撑新要求时补取缺少的帧。 |
| 分析 | 输入材料、分析口径和要求匹配时复用；要求或相关素材改变时重做受影响分析，原记录留存可追溯。 |

每次刷新保存新的互动快照和获取时间，不因互动数字变化自动重新下载或重新识别。无法确定内容是否改变时标注待核对，不能仅凭作品 ID 断言缓存有效。

状态至少分别计数：已发现作品、主页分页状态、素材获取、需要及完成转写、视觉核对、逐条分析，以及失败／待处理项；每项说明自己的分母。恢复后继续未完成阶段，已成功结果不重复产生付费请求。

## 验收标准

1. **分页与恢复**：用包含置顶、重复 ID、视频、图文及多页结果的测试数据验证去重、逐页保存和断点恢复。模拟中途失败／未到末页时，已发现作品可交付且主页保持不完整；到末页后才标记本次可访问范围枚举完成。
2. **时间与证据**：输出按发布时间从早到晚，置顶不改变排序，缺失时间单列。抽查各阶段总结与总评能回到具体作品、文字或画面时间点；互动数据有观察时间，图文参与分析。
3. **识别和费用**：新增付费前能展示数量、已知时长、未知项与预计用量；单价不明时不造价。授权的批次只提交所列工作；模拟失败和结果未知时不会自动重发，核对及明确重试后仅重试必要部分。下载任务的 ASR 调用数为零。
4. **逐作品隔离**：模拟一个作品获取超时、另一个成功，成功项仍可保存和续跑；主页分页不受整号共用 90 秒限制，ASR 不被获取期限中断。实际并发和各阶段计数符合配置。
5. **视觉与分析**：视频、图文均保留对应画面；实际阅读多图后可分别找到核对记录和逐条分析。视觉能力不足、缺图或缺口播时显示未完成／不完整，不能用准备材料代替实际阅读。
6. **增量与导出**：第二次运行先刷新主页并发现新增作品；无变化的媒体、转写和帧图得到复用，互动快照更新。改变分析要求不触发重新识别；下载文件脱离缓存可打开，发布文案与对应作品正确关联。
7. **真实场景**：在用户提供目标账号、完成必要的付费授权后，分别记录真实主页分页、作品获取、豆包识别、实际视觉阅读和最终交付的结果；失败或受限项可追溯。离线模拟、本机安装、`doctor` 及既有 1.3.1 验收均不能代替该项。
