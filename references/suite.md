# 抖音脑套件：路由与共用规则

> 本文描述尚未公开发布的 1.3.1 本地源码候选。实际可用性以安装结果、宿主发现能力和任务运行结果为准。

## 选择入口

这是一套共用安装、配置、更新、工作目录和运行时的产品。目标清楚且属于单项时，直接使用对应子 Skill；混合目标、素材或目标不明、配置和维护使用 `dyb-douyinbrain` 总入口。显式调用某个子 Skill 时，按它支持的范围处理已有文字，不将自动触发范围扩大到无关任务。

| 入口 | 职责 |
|---|---|
| `dyb-transcribe` | 抖音或本地音视频转写、校对、相关字幕和导出。 |
| `dyb-analyze` | 单条抖音内容、本地音视频及博主主页分析。 |
| `dyb-download` | 批量下载抖音主页视频与发布文案。 |
| `dyb-write` | 抖音或音视频相关文稿的口播改写、润色与压缩。 |
| `dyb-knowledge` | 按明确要求归档材料或编译知识主题页。 |

子 Skill 自身的 `scripts/invoke.ps1 guide` 返回 `shared_root`、`entrypoint`、`references`、版本和布局；已登记时还返回 `workspace`。源码和安装后的目录关系不同，以实际输出为准。`status=error` 或非零退出表示共享入口缺失或副本不一致等错误，应报告并停止，不猜路径继续执行。其余命令可通过同一子 Skill 入口转给共享运行时。调用子 Skill 是当前 Agent 加载并执行指令，不会自动创建额外 Agent；博主视觉核对的可选并发条件仍以 [creator.md](creator.md) 为准。

## 首次介绍、更新与配置

共用一份首次介绍状态。安装前按 [onboarding.md](onboarding.md)（英文用 [onboarding.en.md](onboarding.en.md)）在聊天中介绍 8 组能力、例子、产出及语音配置需求；安装后用 `welcome` 读取 `onboarding.due` 和准备状态。首次使用待介绍或用户要求介绍时，实际展示后才执行 `welcome --acknowledge`。标记只代表已展示，不代表用户理解、授权或真实云端验证；从任一入口介绍后不需每个子 Skill 重复介绍。用户已说明目标时介绍后直接继续。

新任务先按 [runtime.md](runtime.md#版本检查与升级) 调用 `check-update`；仅在 `should_notify=true` 时提示更新。检查不可用时报告实际情况并继续不依赖它的任务。用户明确要求更新套件时由总入口执行 `update --apply`，按结果重读新入口；配置或迁移按 [setup.md](setup.md) 和安装指南处理。任何入口共用设置和凭据，用户指定的路径优先，不需要为每个子 Skill 配置一遍。未登记工作目录时，已有文字仍可由 Agent 直接处理；需要持久化任务时按实际工作目录配置或使用运行指南的纯文稿入口。

## 执行与交付

- 目标明确直接执行，沿用本次和此前仍有效的授权；仅素材或目标确实不清时问最关键的问题。普通主页转写需要范围；明确的全量博主分析或下载不重复询问范围。
- 已有文稿直接处理并保留原文，不调用语音；音视频按 [runtime.md](runtime.md) 获取音轨、调用豆包语音，再由 Agent 按实际能力校对。后台获取与登录、付费重试、有效缓存复用的边界遵循该指南。
- 主页分析或下载按 [creator.md](creator.md)。新增博主语音须先展示本批用量预览并取得本批授权；已授权范围继续沿用。仅标题／发布文案分析和独立下载不调用识别。
- 归档或编译只在明确要求时执行，遵循目标库规则和 [knowledge.md](knowledge.md)。普通 `dy-...` 与博主 `creator-...` 是不同任务，不能把 ID 互换；组合需求读取实际有效产物，没有直接入口时按授权准备、写入并读回，不能伪造原生任务或发布结果。
- 聊天先交实际成果：转写／改稿给正文或标明节选，分析给结论、例证及覆盖，下载给成功／失败和画质，归档给实际写入状态，再附文件。未完成、未查看、未验证和失败部分如实说明。

## 组合任务与续办

跨功能组合或跨原生任务续办时，按[组合任务指南](work.md)使用轻量 `work` 记录，关联真实任务和产物；普通单步任务不强制创建。该记录不执行步骤、不授予语音或发布权限，也不替代读取原生任务及验收。
