# 知识库适配与成组归档

## 何时写入

用户明确要求入库或入库并编译且授权仍有效时才执行。转写、校对、分析、改口播本身都不包含入库授权。首次配置只是设置路径／建立空库，不自动收录历史任务。

跨步骤归档可按[套件规则](work.md)使用 `work` 关联实际材料和 workspace 内的真实发布回执；总记录不代替目标库写入、读回或原有发布入口。

按目标库入口读取现行规则。已有规则优先；新电脑没有库时，按 setup 引导用户指定路径或建立轻量库。当前已配置的受控入口继续沿用，不能因迁移包自带代码而绕过它。

## 原文与校对成组

同批次在同一材料组保存：

```text
<目标库允许的素材目录>/<本批材料组>/
    原文留底.md
    校对逐字稿.md
```

每份文件按原序号整理各条材料，记录标题、作者／来源、原链接或本地文件来源和版本时间。两份文件互相链接。原文正文完整保留；它是核查参考，日常查阅和知识编译优先校对稿。

具体前缀、字段、frontmatter 和索引遵守目标库规则，不强制改造已有库。若目标库采用扁平文件，使用同一批次前缀成组并互链；需要自定义归档文件时，在同一 workspace 目录准备两个文件后登记。原始 ASR 文件仍保留本地，不用知识归档覆盖它。

```powershell
# 默认准备同组两份 Markdown，尚未写知识库：
& $dyPython -X utf8 $dyBrain archive <task>
# 按目标库规则调整格式/路径后重新登记；正文应完整保留：
& $dyPython -X utf8 $dyBrain archive <task> --target-prefix '<库内材料组目录>' --raw-file '<原文留底.md>' --reviewed-file '<校对逐字稿.md>'
& $dyPython -X utf8 $dyBrain preview <task>
```

登记会验证原文与校对正文均完整、来源未改、文件互相引用。默认模板只是待入库材料，仍须按库内规则核对和补充所需字段。口播改写稿只在用户点名时作为额外衍生材料收录，不借原稿收录自动发布改写稿。已登记口播正文后使用 `archive <task> --include-spoken --evidence <用户点名收录原话>`，将口播稿与来源一起归组；按目标库格式自备文件时还可传 `--spoken-file`。

## 编译

入库并编译时，先查相关主题页，有合适页面优先扩写。知识页使用目标库要求的来源字段，引用本批校对稿库内路径，必要时关联原文留底。第三方观点标注归属，AI 整理保持草稿；用户审核另行记录。

已有页读取后记下 SHA-256，写入前核对版本。不要只改 sources 或索引就声称主题知识已编译。

## 发布方式

### 已配置个人助手受控入口

仅在 workspace 配置中指定实际 `assistant_root` 且职责、知识库路径匹配时可用：

```powershell
& $dyPython -X utf8 $dyBrain publish <task>
# compile 在同一事务携带知识页：
& $dyPython -X utf8 $dyBrain publish <task> --page '<项目内知识页.md>' --target '<库内主题页.md>' --expected-sha256 -
```

已有页的 expected-sha256 使用读取时的真实值，新增页用 `-`。入口承担串行、索引、日志与受控提交。发布失败或结果未知，先核对原事务和实际回执，使用原 manifest 续办。

### 目标库其他入口／新建轻量库

按该库规则完成写入和索引更新，不绕过已有发布入口。新建轻量库使用本地 Markdown 文件：新材料不覆盖既有文件，更新主题页先比对读取时的版本，再按规则写入。

实际完成后在 workspace 内写回执并读回核对：

```json
{"files":[
  {"source":"<workspace 内原文归档绝对路径>","target":"<库内原文相对路径>"},
  {"source":"<workspace 内校对归档绝对路径>","target":"<库内校对相对路径>"}
]}
```

compile 还需列出实际主题页。然后运行 `record-publication <task> --receipt '<回执.json>'`。此命令只读回校验目标文件与来源哈希，不会替 Agent 写入、更新索引、提交 Git 或判定用户已审。

回执验证通过后报告实际库内路径。未能写入、仅生成待入库文件或仅更新索引时，明确报告当前阶段，不能称已入库。
