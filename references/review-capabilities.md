# 按当前 Agent 的实际能力校对

先通读本次全部识别正文，标出数字、专名及与上下文或画面可能冲突的疑点，再确认本次会话实际能用的工具，按需准备对应范围，不按 Agent 品牌推断。所有方式保留机器原文、结构化结果和原始媒体；Agent 把校对稿另存。

| 可用能力 | 做法 |
|---|---|
| 读写文件、运行命令 | 阅读识别结果做文本校对，无法核实的专名、数字等如实标疑。 |
| 能打开并理解本地图片 | 准备并实际查看帧图，对照画面、识别文本和疑点；读取本地图片不需要 Computer Use。 |
| 能向模型或听音工具输入音频并理解 | 定位已保存的音轨并实际听取疑点。仅能给用户播放音频，不等于 Agent 能听懂。 |
| 同时能看图和听音 | 结合两者：音频用于核对实际说话，画面提供辅助依据。 |

图片或文字里的字幕可能经过改写，不能单独证明说话内容；画面与识别冲突且无法听音确认时保留疑点。没有看图或听音能力时继续文本校对，不声称已核实声音或画面。

## 准备材料

使用 [runtime.md](runtime.md) 中的 `$dyRun` 和实际任务 ID：

```powershell
& $dyRun prepare-review <task>                          # 原文与结构化结果
& $dyRun prepare-review <task> --images                 # 能看图时准备帧图
& $dyRun prepare-review <task> --audio                  # 能听音时复用本地音轨
& $dyRun prepare-review <task> --images --audio         # 同时能看图和听音
& $dyRun prepare-review <task> --images --audio --cached-only  # 只使用已有材料
& $dyRun prepare-review <task> --images --item 1 --start 12 --end 14 --every-frame
```

用户明确只看已有材料时，加 `--cached-only`：可从已有本地视频抽帧，原媒体或音轨缺失时只报告缺口，不联网补取。默认需要画面且旧任务缺少完整视频时，可通过限时获取链路刷新素材，不调用 ASR。

`--item` 是任务成功结果中的序号，从 1 开始；`--start` 和 `--end` 是原视频秒数，帧图区间包含两端，包括恰好位于结束点的帧。默认以 ASR 语句位置与画面下半区域变化抽样，画面变化每秒采样两次。这是帮助定位的画面变化检测，不是 OCR，也不保证捕捉所有字幕变化。字幕在其他位置或切换较快时，可对疑点区间使用 `--every-frame`。

默认每条最多准备 120 帧，可用 `--max-frames N` 调整。抽样结果查看候选数、选中数与是否缩减；指定区间逐帧超出上限时报告缺口，缩小区间或按需提高上限，不能把不完整结果说成覆盖全部帧。

该命令不调用 ASR、不产生新的语音识别费用，也不完成校对。输出为 `prepared`／`prepared_with_gaps`，包含 `items`、`manifest`、实际能力标记、`cloud_asr_called=false` 和 `review_completed=false`。图片、音频不可用时按报告说明缺口。路径按输出中的 workspace 定位；音轨分片的起点与片内听取范围按报告字段对应原视频时间。

新识别使用同一本地媒体提供音轨与画面并记录源文件哈希；旧识别结果缺少来源绑定时报告 `legacy_unrecorded`，不能据此声称音画已经证实同源。范围、抽帧参数及源文件哈希一致且缓存文件校验通过时，复用已准备的帧图；重叠区间也可按源文件哈希和原始帧序号复用校验通过的图片，时间戳对应同一原始帧。未命中的帧先定位再提取，输出所需帧后停止，沿用既有 JPEG 质量设置。音轨分片以缓存校验结果为准。原媒体变化、无法确认来源一致或只有音频时，保留现有结果并说明不能核查的部分。

## 实际核查与记录

实际打开所需图片或听取音频后，按 [content.md 的校对检查记录](content.md#校对检查记录)记录本版使用的方法、检查范围、关键更正依据和未解疑点。只记录实际看过的帧或听过的区间；读到 manifest、生成帧图或播放给用户都不等于 Agent 已核查。

完成检查后继续 `register-review` 与交付。`review_completed=false`、`reviewed=false` 和 `listened=false` 表示程序只准备了证据；真实校对由 Agent 的检查记录证明。

## 博主全量分析

博主任务使用 [creator.md](creator.md) 的 `capabilities`、`prepare`、`claim` 和 `record` 接力，与普通 `prepare-review` 的登记方式不同。`prepare` 把全文、原始图片及视频帧打包；一次阅读分别留下校对和逐条分析，只有实际看过的图片才能登记为已查看。

宿主能并行运行独立视觉任务、核对者能实际打开图片且资源允许时，可先试最多 2 路；否则使用 1 路或说明无法视觉核对。Python 的帧图准备线程不调用视觉模型，领取核对包也不等于已读图。时间阶段与账号报告由主 Agent 在逐条核对后按发布时间归并。
