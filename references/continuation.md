# 恢复任务与复用已有材料

用户说“继续”、重复给出素材或要求修改旧稿时，先查已有任务。恢复由当前 Agent 触发，适用于同一工作区跨聊天或应用重启；没有常驻后台。用户明确了最终目标，就在现有有效授权内继续各步骤，不在每步结束后再次询问是否继续。

## 找到任务，读取下一步

```powershell
& $dyRun resume
& $dyRun resume --input '<原素材>' --purpose rewrite --instruction '<此前的改稿要求>'
& $dyRun resume --input '<原素材>' --request '<组合任务的完整原话>'
& $dyRun resume --task <dy-、creator- 或 work-ID>
```

该命令只读本地记录和文件，不联网、不识别、不执行返回动作。`matched` 表示来源和目标明确且唯一匹配；`choose_task` 返回候选，Agent 根据对话选择，仍有多个可能才集中询问一次。它不做语义猜测，也不联网解析短链。文字不同但语义相同的目标由 Agent 阅读候选后判断，再传明确 ID。新素材或新目标不能因为路径或描述相似而覆盖旧任务。

`recovery` 给出目标、素材范围、有效成果、缺口和 `next_actions`。Agent 读取相应原生任务的真实授权和产物后执行下一步；每步实际完成后登记，再重新 `resume`，直到完成原目标或留下确实需要用户决定的缺口。`work` 的独立步骤可以继续，依赖过期或部分产物的步骤按原依赖规则处理。恢复摘要不授予语音、归档或发布权限。

“继续”沿用保存的素材范围和观察时间；“更新到最新”才刷新主页。普通任务恢复获取／识别使用 `run <task> --saved-scope`，仅处理已有 `jobs.json` 中的作品；尚无已保存范围时如实说明，不能把新扫描说成恢复。博主任务直接沿原清单续办，不先调用 `discover`。失败或结果未知的付费请求先查状态，重试仍需要用户明确指令。

中途退出时，已保存但尚无成功结果的条目也计入缺口，即使来不及写失败回执。先交付已有部分时，交付记录保留这些缺口；离线派生同样继承，不能把成功子集当作完整范围。

## 文稿修改和逐条保存

```powershell
& $dyRun register-review <task> --item <素材ID> --file '<本条校对稿.txt>'
& $dyRun register-spoken <task> --item <素材ID> --file '<本条口播稿.txt>'
```

`--item` 与 `--file` 可按相同顺序重复，只登记本次完成的成功素材，保留其他条目。不带 `--item` 保持原来的整批登记方式。登记不代表 Agent 已完成尚未实际做过的核对。

只登记部分校对稿时仍等待其余条目；`finish-analysis` 会重新校验全部成功素材的校对登记和文件版本，不能用旧的就绪状态跳过检查。

新登记会保存不可覆盖的版本快照和来源依据。`working_content` 区分未登记、有效、被编辑、缺失、依据过期和不可读。被编辑的文件保留；Agent 先读取当前文件与 `snapshot_file`，必要时查看截取的 `diff`，明确基准后续改、另存并登记。差异摘要被截断时读完整文件。只有基准或关键事实无法判断时才询问。旧任务没有快照时，不虚构改动前正文，可参考旧交付文件或说明缺口。

上游校对变化后，只复核受影响的口播或分析；已有交付及人工编辑保留。逐条独立成果继续做，整批综合结论有缺口时先处理缺口或取得接受部分范围的明确决定。部分交付始终标明覆盖范围。

## 旧材料换角度

```powershell
& $dyRun reanalyze <dy-task> --instruction '<新的分析问题，来自用户实际要求>'
& $dyRun creator reanalyze <creator-task> --instruction '<新的分析问题>'
```

返回新的原生任务 ID，原任务及结论保留。普通任务复用有效的原稿和校对稿，并继续分析交付。博主任务冻结原清单、观察时间和已有素材，不继承新付费请求的授权。离线任务不能调用 `discover`、`run` 或申请识别用量；需补获取或识别时说明原因并建立相应在线任务。

博主任务继续 `creator prepare` → `claim` → 实际分析 → `record` → `report`。`prepare --cached-only` 可在普通博主任务中限制为本地材料；离线派生任务自动遵守该限制。有效的已领取／待领取包会保留，不因再次准备丢失进度；强制 `--reanalyze` 前先结束或释放领取。

此前只有部分核对时，重新准备会检查当前可用图片、封面及转写；强制 `--reanalyze` 会按本次抽帧参数准备。历史核对可作为可选依据保留，新补齐的图片仍须实际查看。

新任务不继承旧会话工具能力。当前确实能看图时，创建离线博主任务可加 `--images`，或先用 `creator capabilities <task> --images` 登记；可选并行同样按当前能力声明。

核对包含 `previous_review` 时，可读取其实际证据并在结果的 `review` 中填写 `{"reuse_previous": true}`。程序复核来源、文稿及图片版本并记录 `reused_from`；这代表复用历史核对，不能声称当前 Agent 重新看过图片。当前新看过的图片仍填 `viewed_images`；补帧仍用 `creator detail`，补查清单按原规则登记。新问题必须生成新的逐条分析和独立报告，不能直接沿用旧结论。

旧证据不足时，先用实际工具补查本地材料；仍不足则交有依据的部分和具体缺口。用户要求完整分析时，任务保持未完成。长任务及时保存阶段成果，聊天给有意义的简短进度；用户要求提前查看时交阶段正文，最终仍按原要求在聊天展示成果并附文件。
