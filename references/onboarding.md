# 首次介绍与自然语言路由

> 本文包含待发布的个人知识库候选设计；该部分是否可用以实际安装版本和任务结果判断。

## 先向用户介绍

用户首次安装、首次使用或要求了解功能时，先在聊天中用简短自然语言介绍下面 9 组能力、用途、一个例子和产出，同时讲清语音配置哪些时候需要、哪些时候可以跳过。可根据用户语言组织，不必照搬表格；不要只给文件路径或让用户记命令。介绍覆盖全部功能，但不因此执行全部功能。

| 能做什么 | 一句话例子 | 主要产出及语音配置 |
|---|---|---|
| 提取文字与校对 | “把这个视频转成文字，核对人名。” | 可读逐字稿和文件；媒体转写需要豆包语音，已有文字校对不需要。 |
| 分析内容与博主 | “分析这条视频的开头。”／“分析这个主页视频和图文的选题变化。” | 有例证的单条或账号分析；视频语音识别需要豆包语音，博主批量还需本批用量确认。只分析主页标题／发布文案可停在元数据，不需要识别。 |
| 下载主页视频 | “下载这个主页的视频和发布文案，优先最高可用画质。” | 视频及发布文案，说明成功、失败和画质；不调用豆包语音。 |
| 修改或压缩口播 | “把这篇稿子改短一点，保留开头钩子。” | 保留原稿的独立改写稿；处理已有文字不需要豆包语音，先转写视频则需要。 |
| 整理与导出 | “把这几条整理成一个 TXT。”／“校对这份 SRT，保留时间码。” | 按原顺序交付文稿；已有 SRT 由 Agent 直接处理并另存，保留时间码；识别结果有分句时间才可导出 SRT。已有文字不需要豆包语音。 |
| 按需入库 | “把这批原文和校对稿入库并编译主题页。” | 按目标库规则写入、报告实际状态；按明确要求或已开启的范围入库或编译，语音是否需要取决于上游素材。 |
| 个人知识库 | “建生活、工作、学习知识库；先从工作聊起。” | 新库先选开始方向，三方向默认参与；旧库保留原收录授权。每轮一个问题，相关日常任务中主动查资料、保存明确变化与成果；无需语音 Key。 |
| 续跑与重新分析 | “接着上次做，只处理没完成的部分。” | 复用有效结果、补未完成项；重新分析不自动重新识别，付费失败重试按用户明确要求执行。 |
| 配置和维护 | “教我配置语音。”／“检查环境。”／“更新承意。” | 配置指导、可用状态、迁移或更新结果；按当前事项决定是否需要语音配置。 |

安装或首次配置时先介绍，再沿用已有配置并按当前目标只补必要信息。用户指定的工作目录、知识库和安装位置优先。没有语音 Key 仍可处理已有文字和下载主页视频；抖音登录不是前置。用户需要识别时，再分步引导用户在本机配置，绝不在聊天中索要 Key。只有用户要求入库时才需要选择已有知识库或创建空库；创建空库不等于写入内容。

总入口和六个子 Skill 共用同一份介绍状态、配置与工作目录；从任一入口已经完成介绍，不必为其他子 Skill 重复。明确单项需求分别走 `cy-transcribe`、`cy-analyze`、`cy-download`、`cy-write`、`cy-knowledge`、`cy-vault`，组合或不明确需求与维护走 `cy-charmyee`；职责见[套件规则](suite.md)。自动发现是否生效取决于宿主，调用子 Skill 由当前 Agent 执行，不自动创建额外 Agent。

如果用户已经说明任务，介绍后直接继续，不再问一遍用途。只有素材或目标确实无法判断时问一个最影响执行的问题，例如单独收到链接时询问“你想转文字、分析内容，还是下载视频？”；普通主页转写缺少范围时补问最新条数、日期范围或全部。全量博主分析或全量下载已明确时，不再询问范围。

## 已安装时如何触发

调用 `welcome` 只读取得本机准备状态和功能介绍；命令和字段以[运行命令与状态](runtime.md#首次介绍与配置状态)及实际输出为准。安装器、`init` 和 `doctor` 的引导提示可指向指南和该命令。安装前没有可用入口时直接用本页介绍，安装完成后再核对状态。

当输出表明本版本的介绍尚未展示，或用户明确要求介绍时，Agent 要在聊天中真正讲清上面 9 组，再根据实际状态概括可用项及缺项。完成展示后才运行 `welcome --acknowledge` 记录本版本已展示；它只表示 Agent 已展示，不代表用户读懂、同意付费、已完成云端验证或已授权执行其他任务。仅运行安装器、`init`、`doctor` 或 `welcome` 都不会自动标记已展示；获取介绍失败时可直接使用本页并说明无法登记的实际原因。

## 完整工作流

首次介绍（到期或用户要求时）→ 识别素材与用户目标（不清楚才问一个关键问题）→ 按目标补必要配置 → 先检查已有成果与有效缓存，主页新一批任务刷新可访问作品 → 执行本次所需的获取、识别、校对、分析、改写或入库步骤 → 核对实际内容与覆盖范围 → 聊天先给真实结果，再附文件 → 未完成部分按需续跑。已有文字跳过媒体获取与语音识别；只看主页标题／文案跳过媒体下载与识别；只下载跳过识别与分析；没要求入库或编译就跳过对应阶段。博主批量新增语音先展示用量并取得本批授权；失败或结果未知的付费请求核对后按用户明确指令重试。

## 按用户原话选择路线

由宿主 Agent 结合本轮素材、上下文和用户原话理解意图；`welcome` 只提供介绍与本机状态，不是语义分类器。明确目标直接执行；多个目标依顺序组合，尽量复用已验证缓存，已开启范围内主动积累，其余不增加未授权步骤。博主任务和普通文稿任务的 ID 不能互换：`export-srt`、`archive` 等普通命令不能接收 `creator-...`。若组合目标跨两套任务，依据实际可用的源转写和目标库规则处理；没有对应入口时由 Agent 按规则准备、写入并读回，不伪造已完成的命令或回执。

需要串联组合步骤或跨任务续办时，按[套件规则](work.md)查找或创建 `work` 总记录，关联真实原生任务及文件；单步任务不强制创建。它不执行步骤，也不替代付费识别授权、实际内容检查或发布回执。

| 用户实际目标 | 路线与边界 |
|---|---|
| 单条／批量视频或本地音频转写 | [运行路线](runtime.md#建立与执行任务)：记录实际用途、获取／提取音频、用豆包语音识别，再按现有能力校对和交付。 |
| 已有文字校对、分析 | 保留原文，按 [文稿协作](content.md) 直接处理；已有 TXT／Markdown 可批量 `plan-text`，不调用语音识别。 |
| 分析单条内容 | 使用已有文字，或按需先转写／查看实际画面；结论引用可核对的内容，说明未看、未听或无法获取的部分。 |
| 分析主页全部内容与选题 | [博主分析](creator.md)：发现当前可访问的视频和图文，检查覆盖与视觉能力，展示新增语音用量并在本批授权后处理，逐条依据汇总账号和时间变化。 |
| 只分析主页标题／发布文案 | [主页元数据分析](creator.md#只分析标题或发布文案)：发现并导出标题、文案等元数据，Agent 基于这些文字分析；停在此范围，不调用识别、不声称看过完整作品。 |
| 只下载主页视频 | [独立视频下载](creator.md#独立下载主页视频)：发现后下载可获取视频与发布文案，不做语音识别或完整账号分析；报告实际画质。 |
| 口播改写、压缩 | [文稿协作](content.md#把改稿要求落实到本批)：按实际要求另存，保留原文；显著压缩时记录前后对照。 |
| 批量 TXT 或已有 SRT | 多份 TXT／Markdown 可批量处理并按原顺序交付；已有 SRT 直接读取并按要求另存，保留原编号、时间码与未要求修改的结构。`plan-text` 不接受 `.srt`，不得宣称已提供专用 SRT 导入。识别结果已有分句时间时才可 `export-srt`，见 [runtime.md](runtime.md#复用与重试)。 |
| 入库／入库并编译 | 分别按明确授权执行 [知识库流程](knowledge.md)；先适配目标库，成组保留来源，按明确要求或已开启模块范围整理主题页。生成待入库文件不等于实际写入。 |
| 续跑、重新分析、重新识别或重试 | 先区分意图：[续跑](runtime.md#复用与重试)复用成功缓存；[重新分析](creator.md#实际阅读校对和逐条分析)时，原目标可用 `--reanalyze`；仅对已有材料换角度就读取已核对材料另存报告，标明原覆盖范围与观察时间，不刷新主页或伪造旧缓存；要求基于当前主页重新分析才用新 `instruction` 建任务并发现作品，复用有效媒体与转写。重新识别另存版本；失败或结果未知的付费识别先核对，再按用户明确要求重试。 |
| 配置、教程、环境检查或获取排障 | 读 [配置与迁移](setup.md)、[语音配置教程](doubao-setup.md) 和 [运行与状态](runtime.md)；只解决实际缺项。常规获取在后台；仅用户明确要求登录、验证或界面排障时打开可见浏览器。 |
| 迁移、检查更新或升级 | 迁移遵守 [安装指南](../INSTALL.md)；[检查更新与升级](runtime.md#版本检查与升级)分开，用户要求升级时才安装。 |

## 聊天先交付结果

先让用户在聊天中看到真实成果，再附文件和必要的记录：

- 分析：给出主要结论、具体作品／原文／实际查看画面的例证，以及覆盖范围与缺口。
- 转写、校对或改稿：贴可读正文；过长时明确标注节选并说明总量、未完成或未解疑点，再附完整文件。
- 下载：给出成功与失败数量、实际画质或无法判断的画质、保存位置，以及未发现完整主页等限制。
- 入库：先概述材料或主题，再说明实际已写入、仅准备还是失败，并提供相应路径或回执。
- 配置、维护：说清改了什么、当前哪些功能可用、哪些仍待配置或真实验证。

有失败或尚未取得结果时直说实际阶段，不编造结论。部分结果说明成功／失败范围；不承诺抓到平台的全部作品或在后台永久运行。文件、任务状态和准备材料不能代替聊天中的实际结果，也不能代替用户验收。

## 可选个人知识库

主动介绍 cy-vault：“我也可以建立生活、工作、学习知识库；你选一个先聊，三个方向都会参与，之后在相关日常任务中结合资料、记录明确变化和成果。” 用户选择后再开启，不阻断当前任务。新库访谈每轮问一个核心问题并持续进行；普通任务优先照常完成。配置作用范围、主动积累、本次不保存、旧库迁移和失败续办见[个人知识库](personal-vault.md)，方向问题见[个人知识方向](personal-domains.md)。
