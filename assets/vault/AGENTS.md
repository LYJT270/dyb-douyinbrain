# 个人知识库约定

先读 SCHEMA.md、SOURCE_OF_TRUTH.md 和 index.md，按任务查相关资料。

用户内容按 `生活/`、`工作/`、`学习/` 三个顶层方向组织，内部目录按需生长；公共个人档案放在 `生活/个人档案/`，工作项目或账号资料保留场景范围。规则、导航与运行状态等控制文件可留在库根。保留原始材料，第三方观点注明归属，不据此推断用户身份。区分用户原话、明确事实、主观感受和未确认推测；未知保持未知，不混入事实。

用户通过 cy-vault 开启方向和作用范围后，在该范围内主动查资料，保存明确提供的新事实、状态变化、目标变化、实际结果，以及交给 Agent 处理的材料、实际交付的文稿与有依据的分析成果，并更新相关主题和索引。无需等待用户逐次要求“记住”；普通闲聊不全量收录。临时不保存、暂停和后续范围变更优先。仅创建空库或绑定目录不启用自动积累，也不追溯收录历史任务。

新库先让用户选择从生活、工作、学习哪一方向开始；该选择只决定先聊哪里，三方向默认都参与。访谈每轮问一个核心问题，直到用户暂停、停止、拒答或换话题；不因基础字段齐全而结束。已有材料先读，明确任务优先，普通任务不强制采访。跳过、暂停和拒答的方向不催问；可先查现有材料，再偶尔邀请开始未启动方向。保留回答原话及其类型，阶段性展示资料供纠正。

以上范围默认适用于新库。旧库需保留原收录授权；旧 `creative` 范围映射到 `work`，`pending_domains` 标出尚未授权的方向。目录迁移和 Host 入口更新不扩大授权，只有用户明确同意全部方向后才运行 `kb enable --all-domains`。

同组原文与校对稿分别保存并互链；改写与分析保留来源。主题页标注草稿，引用实际来源。学习进度依用户反馈、练习或复述记录，不以 Agent 已讲解推断掌握。

新旧库之间迁移时，先读现行规则、全部用户内容和写入入口，为全部文件展示 `source → target` 映射及链接、索引、状态变化、冲突、备份和恢复预览。用户完整查看后一次确认再迁移；尊重旧库的受控发布入口，保留原文和历史记录，迁移后逐项核验并保留回滚，不清理旧文件。

更新前读取当前文件和版本，保留人工修改；原始材料不可覆盖。写入后读回并更新 index.md，待保存不等于已保存。失败时先交付已完成的任务成果，保留待处理记录，恢复时先核对实际文件，避免重复写入。不自动提交 Git、发布到外部或创建定时任务。
